# State Roundtrip Kit

「保存したはずの値が、開き直しても残っているか」を調べる小さな Swift パッケージです。[English](README.md)

## できること

- レコード数・ID・フィールド名・値の厳密比較。順序だけは無視します。
- 値や ID を含まない差分診断。
- 準備 → 起動 → 入力 → 保存 → 終了 → 再起動 → 読み戻し → 比較、の結果記録。
- テスト専用の一時ディレクトリと、所有確認付きの明示的な削除。
- 既存の XCTest UI テストへ組み込む、入力・保存・終了・再起動のサンプル。

XCTest の代用品でも、どのアプリでも自動でテストできるツールでもありません。アプリ側の保存完了・専用データ領域・読み戻しの実装が必要です。

## 検証状況

2026-10-21 に、独立した macOS 27.0.1（Apple Silicon）／Xcode 27.0／Swift 6.4 環境でコアのビルドと XCTest 14 件が成功しました。iOS UI サンプルと架空データ専用ホストのコンパイル、既存 iPhone 18 Pro／iOS 27.0 シミュレーターでの UI テスト 5 件も成功しました。UI 実行結果・修正・証拠・制限は `VALIDATION.txt` に分けて記録しています。CI、Linux／Swift 5.9、旧 OS、実機は未検証です。付属 CI は Linux の Swift 5.9 と macOS ランナー付属 Swift でコアテストのみを実行する構成で、iOS UI テスト 5 件は実行しません。JSON ファイルを書いて読むテストと、アプリの再起動検証は別です。

## 導入

Swift 5.9 以降。Foundation コアは Linux / macOS、iOS 15 以降を想定していますが、対応マトリクスの実測ではありません。

1. このフォルダで `swift test` を実行します。
2. Xcode の既存プロジェクトにローカル Swift Package として追加します。
3. テストターゲットに StateRoundtripKit をリンクします。
4. `Examples/RoundtripUITests.swift` を既存の iOS UI テストターゲットへコピーします。
5. アクセシビリティ ID と TextField / TextView を実装に合わせ、シミュレータで実行します。

サンプルは Swift Package のテスト対象に含めていません。UI を動かさずにパッケージテストが通っても、UI 検証済みとは言えません。

既存アプリを使わず試す場合は、`ValidationHost/RoundtripValidation.xcodeproj` を開きます。専用バンドル ID と DEBUG 専用ストアを持つ架空データ用ホストです。

## アプリ側で必要な対応

- DEBUG 専用の起動引数 `--roundtrip-fixture <ID>` を解釈し、通常データを開く前に専用ストアへ切り替えます。不正な ID を拒否し、通常ストアへのフォールバックは禁止します。
- 同じ ID で再起動したときはデータを保持します。起動ごとのリセットはしません。
- ネットワーク・同期を無効化し、専用ストアの読み込み完了後だけ `roundtrip.isolated-ready` を表示します。
- 入力変更時に `card.saved` を消し、保存が完了したときだけ新しい完了表示を出します。サンプルは Save 操作前に古い表示がないことを確認します。専用ホストでは保存世代も更新し、回帰テストで変化を確認します。
- UI サンプルは選択した一つのフィールドだけを確認します。全件検証には、専用ストアの全 ID・全フィールドを取得するアダプターが必要です。
- 後始末は専用 ID のストアだけを明示的に削除します。通常データ削除やアンインストールは行いません。

アプリと UI テストのプロセスは別のサンドボックスです。FixtureDirectory のパスを共有ストアとして渡さず、ID を渡してアプリ側に専用領域を作ります。

## 実際のつまずきを切り分ける

入力後は実際の値が期待値と一致するまで待ち、確認できてから入力ステージを成功にします。空欄のプレースホルダーが入力値として取得される場合があるため、期待値と異なる文言にしてください。

固定秒数の sleep ではなく、保存完了・画面の準備完了・値の一致を待ちます。キーボードで隠れた入力欄、TextField と TextView の違い、保存前の読み戻しを、永続化バグと混同しないための記録が目的です。

帳簿なら架空の金額を編集して保存・再起動・全件比較。カードなら問題文編集で承認解除、保存、再承認、再起動後の復習位置まで、各段階の期待値を別々に用意します。これは応用案であり、実アプリで実行済みという意味ではありません。最初に期待値を一つわざと変え、失敗を検出できることも確認してください。

## 比較・安全上の注意

ID 重複と空 ID は拒否します。空文字と未存在は別、余分なレコード・フィールドも不一致です。数値・日付は呼び出し元で明示的な文字列表現に統一します。順序が意味を持つ場合は位置をフィールドに含めます。渡されていない情報は検証できません。

差分は種類・位置・件数だけを返し、元の ID・フィールド名・値を保持しません。ただし Snapshot / Record 自体には入力値があるためログ出力しないでください。診断コードにも固定文字列を使い、個人情報や生のエラーメッセージを含めません。

全ステージが順番どおり一回ずつ passed のときのみ ScenarioReport.passed が真になります。これは記録モデルであって、自動実行や成功の証明機構ではありません。未実施を成功として記録しないでください。

FixtureDirectory は新規の一時ディレクトリしか作成せず、任意のアプリ保存先を受け付けません。cleanup は所有マーカーとパスを確認し、ルートのシンボリックリンク差し替え等を拒否します。ただし同時に別プロセスが書き換える攻撃への防御ではありません。使用・削除中の並行変更は禁止です。
